# 需求整理：科研绘图从「面板工具」到「会话原生能力」

状态：v1.1–v1.3 已实现（2026-11-09，见 CHANGELOG 1.2.0）
日期：2026-11-09
对象：`dsh-sci-plot` v1.1–v1.3 规划与实现

---

## 0. 一句话

把科研绘图从「用户打开面板去操作的插件」变成「AI 在会话里自主使用的能力」：用户只描述需求，AI 自己判断要不要图、自己选图种/学科风格/数据映射、自己渲染和质检、把图直接放进回答里，并且能用一句话继续改；面板不取消，退化成可选的「检查 + 精修 + 导出」工作台。

---

## 1. 我理解的四层意思

### 1.1 从「用户点名」到「AI 自主判断」
不是只在用户说出「画图」两个字时才触发。用户在聊数据、要分析结论、准备论文/报告/汇报时，图和文字是同一件事的两面，AI 应该主动判断「这里配一张图会明显更好」并直接做出来；反过来，纯代码、闲聊、文案类任务不插入图。判断权在 AI，不在用户的措辞。

### 1.2 从「工具步骤」到「会话自然动作」
用户不需要知道 kind、spec、domain、journal、工具名。AI 内部完成：找到/读取数据 → 字段画像 → 选图种 → 选学科与期刊风格 → 生成映射 → 渲染 → 质检 → 必要时修正。回答里只出现「图 + 一句图注 + 一句结论/注意点」，而不是 JSON 和参数清单。

### 1.3 从「面板交付」到「对话内联交付」
图应该出现在对话里，而不是让用户切到面板去找。内联图卡要带足够信息（图种、学科、期刊、尺寸、DPI、质检等级），可以点开大图、进面板精修、导出；同时自动进入作品库与面板画廊，两边是同一条数据。

### 1.4 从「一次生成」到「可对话迭代」
AI 要记住这张图（figureId + spec）。用户说「换双栏」「色盲友好一点」「标题改中文」「加显著性」，AI 只改对应字段增量重渲染，并说清改了什么；同一轮/同一份报告里的多张图风格一致；「以后默认 IEEE 双栏 600dpi」这类偏好能沉淀下来，下次默认生效。

## 2. 典型场景（用户怎么说 → 期望 AI 怎么做）

| # | 用户输入 | 期望行为 |
|---|---|---|
| 1 | 附一个 CSV：「帮我看看这组数据有什么规律」 | 不问「要不要画图」，直接画像 + 出 1 张最能说明问题的图 + 写 3–5 句发现；图内联展示 |
| 2 | 「画个火山图，Nature 风格」 | 直接用推荐数据/指定列渲染；阈值线、上/下调配色、top 基因标注齐全；质检 ≥90；不啰嗦参数 |
| 3 | 「这数据适合什么图？」 | 给 2–3 个候选及理由，并直接渲染最优的一张作为预览；不把选择题全丢回给用户 |
| 4 | 「刚才那张改成双栏、色盲友好、标题中文」 | 沿用同一 figureId 的 spec 改 3 个字段重渲染；一句说明改了什么；图卡就地更新 |
| 5 | 「帮我做一组论文配图：生长曲线、剂量反应、生存曲线」 | 统一 domain/journal/画幅/DPI 批量出 3 张；每张一句图注；可一次性导出 |
| 6 | 「这份 Excel 的销售数据做成汇报用的图」 | 读 xlsx、识别字段、按 slide 画幅出图；导出 PNG/PDF；说明数据口径 |
| 7 | 「以后默认 IEEE 双栏 600dpi」 | 写入默认偏好；当前图立即重渲染，后续所有渲染（含面板）默认生效 |
| 8 | 「把这张图导出 TIFF 投稿」 | 用同一 spec 重新导出 600–1200dpi TIFF + PDF/EPS；给出文件位置与质检结果 |
| 9 | 「这张图是不是有问题？」 | 先读数据/统计做诊断，必要时出一张诊断图（残差/分布/QQ）；不硬凑漂亮图 |
| 10 | 修 bug / 写文案 / 闲聊 | 不出图、不提插件、不打扰 |

## 3. 需求条目

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| R1 | **自主触发策略**：把「何时主动出图 / 何时不出图」写进系统提示，覆盖数据分析、论文/报告/汇报准备；无关任务绝不插入 | P0 | 10 个场景测试中，需要图的主动出，不需要图的 0 误触发 |
| R2 | **一键自主编排**：新增 `sci_plot_auto`，输入数据 + 意图，内部完成画像→选型→映射→风格→渲染→质检，一次调用出图；失败可回退到手动工具链 | P0 | 「这数据有什么规律」单次调用出图；延迟 < 5s（本机） |
| R3 | **对话内联图卡**：渲染结果在会话中直接显示为卡片（缩略图/标题/图种·学科·期刊/尺寸·DPI/质检徽标/打开面板/导出）；零模型 token 成本 | P0 | 图在会话可见、可点开、可导出；单图对话 token 增量 < 2k |
| R4 | **可迭代**：figureId 贯穿；改 style/labels/options 增量重渲染；说明改动；保留上一版可回退 | P0 | 「换双栏/改标题」不重问数据、不换图种；可回退 |
| R5 | **风格与偏好**：学科/期刊/画幅/DPI/字体/配色自动匹配；一句话设默认并持久化（面板同源）；会话/报告内风格锁定 | P1 | 设一次 IEEE 双栏，后续渲染与面板默认都变 |
| R6 | **数据接入**：CSV/TSV/JSON 已有；补 xlsx/xls；对话附件、工作区文件、粘贴数据、内置样本都能作数据源 | P1 | 附件 xlsx 直接出图；无需用户转格式 |
| R7 | **质量门**：质检 <90 或关键警告必须修正或明确披露；单位、中文标签、显著性不得糊弄；不静默出低质图 | P0 | 低质图不交付；修复后分数上升；无法修复时说明原因 |
| R8 | **导出与交付**：按用途（投稿/汇报/网页）选格式与物理尺寸；给文件位置；多图打包 | P1 | 「导出 TIFF」一步完成；一组图一次打包 |
| R9 | **面板协同**：AI 的图在面板可见可精修；面板加「交给 AI 继续」回到对话；AI 能读面板最新 spec 迭代 | P2 | 面板改图后 AI 能接着改；双向不打架 |
| R10 | **Token 与性能**：内联图不进模型上下文；单图渲染 < 3s；避免每轮重复 capabilities/inspect；探索阶段不堆图 | P1 | 多轮对话 token 不因图膨胀；重复动作可测 |

## 4. 现状与差距（基于 v1.0.0 实际代码）

**已经有的（不用重做）**
- 6 个 Agent 工具：`sci_plot_capabilities / inspect_data / render / export / figures / doctor`。
- 系统提示小节已注入（`index.js` 的 `PROMPT_SECTION`）。
- 渲染结果已含 `figureId`、`pngUrl`、`thumbUrl`、`previewPath`、质量评分与 warnings。
- 作品库、面板画廊、示例图集、导出、质检共用同一数据源。
- 面板「工作室」可回填 spec，AI 可用 `sci_plot_figures action=get` 读回 spec。

**缺口（v1.1 要补）**
1. **提示词是「工具说明书」而不是「行为策略」**：目前只写「For every scientific/research figure request…」，先 capabilities → inspect → render 三步；没有「分析类任务也主动出图」「无关任务不出图」「意图→图种」「默认一张」「内联呈现」这些行为约定。
2. **工具结果是纯文本 JSON，没有内联呈现**：`lib/tools.js` 的 output.render 只返回 text block；没有自定义 `tool.call.toolview`，所以会话里只有一行 JSON 文本。
3. **没有自主编排工具**：AI 必须自己一步步选 kind / mapping / style；数据和意图已经足够时仍要 3–4 次调用。
4. **偏好不可由 AI 写入**：面板设置存在，但没有工具让 AI 保存「以后默认 IEEE 双栏 600dpi」。
5. **数据源缺 xlsx/xls**：目前仅 CSV/TSV/JSON。
6. **面板与对话单向**：面板只有「在工作室继续调参」，没有「交给 AI 继续」；对话里生成的图进面板没问题，反向没有入口。
7. **无版本/一致性机制**：每次渲染只存一份 spec；同一报告多图没有风格锁；改坏了没有回退。

**技术上已确认可行（本轮已核对）**
- `conversation.chat.node` 的 key 是固定的，不能新增 Chat node 类型；但 `tool.call.toolview` 是**按工具名开放的 key**（`key: 'sci_plot_render'` 即可注册），可以在对话里渲染自定义图卡。
- 作品图片走面板同源 loopback URL（`/dsh-sci-plot/api/figures/<id>/file?...`），图卡用 `<img>` 直接显示，**不需要把图片塞进模型上下文**，因此内联展示零 token。
- 若需要 AI「自己看图」再自审，可复用 `read_image` 同款的 durable attachment 图像块机制（会按图片计 token），默认不做。
- 面板路由已支持缩略图（`variant=thumb`）与多格式文件流，图卡加载成本低。

## 5. 行为契约（「自然」的可验收定义）

**触发**
- 明确要图 > 数据分析需要可视化 > 论文/报告/汇报交付 > 其他；用户没数据时不出图、不编数据。
- 默认每轮 1 张主图；只有用户明确要「一组/多张/每因素一张」或问题本身并列时才批量。
- 无关任务（修 bug、写文案、纯问答）不出图、不提插件。

**选型**
- 用户指定 kind/style 优先；否则按「学科预设推荐 + 数据画像推荐」决策，例如：差异表达→volcano、随访时间+事件→km_survival、时间列→line/time_series、分类+数值→bar/box/violin、多数值列→corr_heatmap/pca、光谱→spectra、衍射→xrd、频响→bode。
- 图表类型不确定时给 2–3 个候选 + 先渲染最优的一张，不把选择题全丢回用户。
- 期刊风格默认取用户偏好；没有偏好时按学科最常用（生命医学→Nature、临床→NEJM、工程→IEEE、化学→ACS……）。
- 图内标签默认英文 + 单位（投稿习惯）；用户要中文或数据本身是中文则全中文。

**呈现**
- 回答 = 图卡 + 一行图注（数据来源/映射/统计方法）+ 一句结论或注意点；不贴 JSON、不列参数。
- 图卡包含：缩略图、标题、图种·学科·期刊、物理尺寸·DPI、质检分数；按钮：打开面板、导出。
- 同时自动写入作品库；面板画廊与对话图卡指向同一 figureId。

**迭代**
- 沿用 figureId + spec，只改用户提到的字段；每次用一句话说明「改了什么」。
- 用户连续 2 次不满意时，主动建议换表达（换图种/改聚合/拆多图），而不是继续微调。

**质量与失败**
- 质检 <90 或存在 fail/warn 时先修（字号、标签、图例、配色、色标），修不动则披露问题并给替代方案。
- 引擎/解释器缺失 → 诊断并给修复步骤；无数据 → 明确要数据或提供样例模板；不静默失败。

**Token 与性能**
- 内联图用 UI 图卡，不进模型上下文；每张图只回必要元数据。
- 同一会话内 capabilities 结果不复重调；inspect_data 只做一次；探索阶段最多 1 张草图。
- 单图渲染目标 < 3s（复合图除外），图卡首屏 < 1s。

## 6. 技术落点（按现有代码结构）

1. **提示词层（P0）**：重写 `index.js` 的 `PROMPT_SECTION` 为行为策略段（约 600–900 字）：触发矩阵、意图→图种速查、默认一张、内联呈现说明、迭代规则、质量门、Token 纪律。保留 `sci_plot_capabilities` 作为一次性的目录查询，不再要求每次从头三步走。
2. **工具层（P0/P1）**
   - 新增 `sci_plot_auto`：Host service 复用 `inspectData` + 推荐 + `render`，参数 `{data:{path|sample|rows}, intent?, domain?, journal?, kind?, size?, dpi?, options?}`，返回 figureId、质量、选定理由、备选图种、图注草稿。
   - 新增 `sci_plot_preferences`：`action: get|set`，读写作品库 settings（与面板设置同源），支持「以后默认……」。
   - 精简 `sci_plot_render` 返回：必要字段 + 缩略图 URL + figureId；完整质检清单放详情接口/面板，降 token。
   - 数据层补 xlsx/xls（Host 用 Python/openpyxl 解析或轻量 JS 库），附件路径继续走 `data.path`。
3. **客户端层（P0）**：`src/client` 新增 toolview 分片，注册 `tool.call.toolview` key `sci_plot_render`（及 `sci_plot_auto`）：
   - `preparing/start` 阶段 → 骨架「绘制中…」（含图种/风格提示）；
   - `result` 阶段 → 解析结果 JSON，渲染图卡（`<img src=thumbUrl>`、标题、chips、质检 badge、打开面板/导出按钮）；
   - 失败 → error + 修复建议；全部使用宿主主题 token。
4. **面板协同（P2）**：作品详情/卡片加「交给 AI 继续」；点击回对话并带上 `figureId` 的提示；AI 用 `sci_plot_figures get` 读取面板最新 spec。
5. **版本与一致性（P1/P2）**：figure 增加 spec 版本链（或每图保留上一条 spec），支持「回退上一版」；同一轮/同一报告使用 style lock（首图确定 domain/journal/size 后沿用）。
6. **验收自动化**：新增集成测试覆盖 auto→render→toolview 数据、preferences 持久化、xlsx 读取、无关任务不触发（提示词行为用评测样例）。

## 7. 验收清单

1. 「这组数据有什么规律」+ CSV：主动出 1 张图，图卡内联可见，回答有结论；用户未提「画图」。
2. 「画个火山图，Nature 风格」：一次到位，质检 ≥90，阈值线/配色/top 基因正确。
3. 「这数据适合什么图」：给候选 + 渲染最优一张。
4. 「改成双栏、色盲友好、标题中文」：同 figureId 重渲染，只改对应字段，说明改动。
5. 「做一组论文配图（3 种）」：统一风格批量出 3 张，图注齐全，可打包导出。
6. 「以后默认 IEEE 双栏 600dpi」：偏好持久化；当前与后续渲染默认生效（面板同源）。
7. 「导出 TIFF 投稿」：600–1200dpi TIFF + PDF/EPS，文件位置明确。
8. 「这张图有问题吗」：先诊断，必要时出诊断图。
9. 无关任务：0 出图、0 插件提及。
10. 无数据/引擎异常：明确失败原因与修复步骤，不静默。
11. Token：每张图对话增量 <2k；多轮迭代上下文不膨胀。
12. 面板双向：AI 图在面板可见可改；面板「交给 AI 继续」能接上。

## 9. 我直接拍板的默认值（你不否决就按这个做）

1. 默认每轮 1 张主图；明确要求才批量。
2. 内联图卡只做 UI 展示，不把图塞进模型上下文；AI 要自审时用 `read_image` 显式读。
3. 图内标签默认英文 + 单位；用户要求中文或数据为中文时全中文。
4. 默认风格跟随插件 settings（当前：生命医学 / Nature / 89mm 单栏 / 300dpi），一句话可改并持久化。
5. 主动出图边界：数据/分析/论文/报告/汇报类可主动；纯代码/闲聊/文案不主动。
6. 质量门：交付图必须 ≥90 分；无法达标必须披露。

## 10. 与 v1.0 的关系

v1.0 已经把「引擎 + 面板 + 工具 + 质检 + 示例」做扎实，v1.1 不改引擎与面板主体，只加三件事：**行为策略（提示词）**、**自主编排工具**、**会话内联图卡**；其余按分期推进。面板保留为精修台，不做替代。
